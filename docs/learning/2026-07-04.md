## Running the Backend

The Maven wrapper (`mvnw.cmd`) is used to run the app without a global Maven install:

```powershell
cd apps/api
.\mvnw.cmd spring-boot:run
```

On Windows, always use `mvnw.cmd` not `mvnw` (that's the Linux/Mac version).

Spring DevTools auto-restarts the app on file save. **Exception:** changes to `pom.xml` (adding dependencies) require a full manual restart.

## Docker

**Core concepts:**

- **Image** — a blueprint/snapshot of an environment (built from a `Dockerfile`)
- **Container** — a running instance of an image
- **Docker Compose** — runs multiple containers together from one `docker-compose.yml`

**Docker runs on WSL 2** (Windows Subsystem for Linux) — a lightweight Linux VM inside Windows. It grabs RAM aggressively. Cap it in `C:\Users\<you>\.wslconfig`:

```ini
[wsl2]
memory=16GB
processors=4
swap=4GB
```

Then run `wsl --shutdown` to apply.

**Daily dev workflow:** run only the DB in Docker, run the app locally:

```powershell
docker compose up db -d        # start DB
.\mvnw.cmd spring-boot:run     # run API locally
```

**Key commands:**

```powershell
docker compose up db -d        # start a specific service in background
docker compose up --build -d   # build images and start everything
docker compose down            # stop and remove containers
docker compose down -v         # also wipe volumes (database data)
docker compose logs -f api     # tail logs for a service
docker ps                      # list running containers
```

## application.properties

Stores app config. Uses `${ENV_VAR:default}` syntax so environment variables override defaults (useful for Docker vs local):

```properties
spring.datasource.url=${SPRING_DATASOURCE_URL:jdbc:postgresql://localhost:5432/musicdecoded}
```

`@Value("${jwt.secret}")` in Java reads a value from this file and injects it into a field.

## Spring Boot Layer Pattern

Every feature follows the same three-layer pattern:

```
Controller  → receives HTTP request, calls service, returns response
Service     → business logic (the actual work)
Repository  → database operations
```

The Android app only ever calls the Controller. The Controller never touches the database directly — it always goes through the Service, which uses the Repository.

## JPA / Hibernate (Code-First)

**Entity** = a Java class that maps to a database table. Hibernate reads `@Entity` classes at startup and creates/updates the tables automatically.

```java
@Entity
@Table(name = "users")
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.UUID)
    private UUID id;

    @Column(unique = true, nullable = false)
    private String email;
}
```

**Key annotations:**

| Annotation             | What it does                                |
| ---------------------- | ------------------------------------------- |
| `@Entity`              | Maps this class to a DB table               |
| `@Table(name="users")` | Sets the table name                         |
| `@Id`                  | Primary key column                          |
| `@GeneratedValue`      | Auto-generates the value on insert          |
| `@Column(...)`         | Customise a column (unique, nullable, etc.) |
| `@PrePersist`          | Method runs automatically before INSERT     |

**Code-first vs database-first:**

- Code-first (what we're doing) — write Java, Hibernate generates SQL
- Database-first — write SQL migrations manually (tools: Flyway, Liquibase)
- `ddl-auto=update` is fine for dev; switch to Flyway for production

**See the SQL Hibernate generates:**

```properties
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
```

## JpaRepository

`UserRepository` extends `JpaRepository<User, UUID>` — an interface that gives you database methods for free:

```java
userRepository.save(user)          // INSERT or UPDATE
userRepository.findById(id)        // SELECT WHERE id = ?
userRepository.findAll()           // SELECT all
userRepository.delete(user)        // DELETE
userRepository.existsById(id)      // SELECT EXISTS
```

**Derived query methods** — Spring generates SQL from the method name:

```java
Optional<User> findByEmail(String email);
// → SELECT * FROM users WHERE email = ?
```

If the field name doesn't match anything in the entity, the app fails at startup — a useful safety net.

---

## Optional\<T\>

A wrapper that forces you to handle the "not found" case instead of crashing on null:

```java
Optional<User> result = userRepository.findByEmail(email);

result.isPresent()     // true = found, false = not found
result.orElseThrow()   // get User or throw exception if empty
result.orElse(null)    // get User or return null
```

Think of it as a box that either contains a value or is empty — you must check before using it.

## Lombok @Data

Generates getters, setters, `equals()`, `hashCode()`, and `toString()` automatically so you don't write boilerplate:

```java
@Data
public class AuthRequest {
    private String email;
    private String password;
    // getters and setters exist — you just can't see them
}
```

## SQL Concepts

**Primary key** — uniquely identifies every row. Can't have two rows with the same value. Using UUID is better than auto-increment (doesn't leak row count, safer to expose).

**Foreign key** — a column that points to a row in another table. Creates a relationship:

```
user_library.user_id → users.id
```

The DB enforces this — you can't reference a user that doesn't exist.

**Nullable** — `nullable = false` means the column must always have a value. `nullable = true` (default) means it can be empty (NULL). NULL ≠ empty string `""`.

## Dependency Injection (@Autowired)

Instead of creating objects yourself, Spring creates and manages them. You declare what you need and Spring provides it:

```java
@Autowired
private UserRepository userRepository;  // Spring injects the real implementation
```

Spring has a container — a registry of objects it manages. When the app starts, Spring scans your code, finds anything marked with those annotations, creates one instance of each, and stores it. When something has `@Autowired`, Spring looks in the registry for the right type and injects it automatically.

```
App starts
  → Finds @Service AuthService       → creates one instance, stores it
  → Finds @Repository UserRepository → creates one instance, stores it
  → Finds @Component JwtAuthFilter   → creates one instance, stores it

AuthService has @Autowired UserRepository
  → Spring looks in registry for a UserRepository → injects it automatically
```

The annotations all do the same thing under the hood — the different names are just for readability:

| Annotation                        | Meaning                                                 |
| --------------------------------- | ------------------------------------------------------- |
| `@Service`                        | "this is business logic"                                |
| `@Repository`                     | "this talks to the database"                            |
| `@Controller` / `@RestController` | "this handles HTTP requests"                            |
| `@Component`                      | "this is a general Spring-managed object"               |
| `@Bean`                           | "this method returns an object I want Spring to manage" |

## Spring Security

**`SecurityConfig`** controls which routes are public and which require a token:

```java
.requestMatchers("/auth/signup", "/auth/login").permitAll()
.anyRequest().authenticated()
```

Any new endpoint you create is automatically protected. Only update `SecurityConfig` if you want to make a route public.

**`STATELESS` session policy** — correct for mobile APIs. No sessions, no cookies. Every request must carry a JWT.

## BCrypt Password Hashing

Passwords are never stored as plain text. BCrypt hashes them one-way:

```java
passwordEncoder.encode("mypassword")        // → "$2a$10$..." (hash)
passwordEncoder.matches("mypassword", hash) // → true/false (never decrypts)
```

If your database leaks, attackers get hashes they can't reverse.

## JWT (JSON Web Token)

A signed string returned after login that the client stores and sends with every future request:

```
Header.Payload.Signature
eyJhbGc...  .eyJzdWIi...  .SflKxwR...
```

- **Payload** stores data like email and expiry
- **Signature** proves it wasn't tampered with
- The server never stores the token — it just verifies the signature

Client sends it in the `Authorization` header:

```
Authorization: Bearer eyJhbGciOiJIUzM4NCJ9...
```

## HTTP Concepts

**`HttpServletRequest`** — Java's representation of an incoming HTTP request. Spring creates it automatically from raw network data:

```java
request.getHeader("Authorization")   // read a header
request.getMethod()                   // "GET", "POST", etc.
request.getRequestURI()               // "/auth/login"
```

**HTTP methods:**

- `GET` — fetch data (no body)
- `POST` — send data / create something (has a body)

**Status codes:**

- `200 OK` — success
- `201 Created` — something was created
- `401 Unauthorized` — no token / invalid token
- `403 Forbidden` — authenticated but not allowed (or route doesn't exist in some Spring configs)
- `404 Not Found` — route doesn't exist
- `500 Internal Server Error` — unhandled exception in your code

## Annotations Summary

| Annotation                 | Layer      | What it does                                  |
| -------------------------- | ---------- | --------------------------------------------- |
| `@RestController`          | Controller | Marks class as HTTP controller returning JSON |
| `@RequestMapping("/auth")` | Controller | Prefix for all routes in this class           |
| `@PostMapping("/login")`   | Controller | Maps POST /auth/login to this method          |
| `@RequestBody`             | Controller | Deserialize JSON request body into object     |
| `@Service`                 | Service    | Marks as a Spring-managed service bean        |
| `@Component`               | Any        | Generic Spring-managed bean                   |
| `@Configuration`           | Config     | Class contains bean definitions               |
| `@Bean`                    | Config     | Method returns a Spring-managed object        |
| `@Autowired`               | Any        | Inject a dependency from Spring's container   |
| `@Value("${key}")`         | Any        | Inject a value from application.properties    |
| `@Entity`                  | Entity     | Map class to a DB table                       |
| `@Data`                    | Any        | Lombok: generate getters/setters/etc          |
| `@PrePersist`              | Entity     | Run method before INSERT                      |
